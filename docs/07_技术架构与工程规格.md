## 2. 横切工程能力（原文明确要求）

### 2.1 候选-审核通道（skill7，A4）
- Critical Skill 输出必须走 Candidate → Review/Confirm → Applied 通道（line 11314）
- skill7 状态机：`ai_suggested→pending_review→confirmed/modified/rejected→archived/applied`（见 05 §2.3）

### 2.2 审计（writeAudit）
- 所有人工操作 + AI Skill 调用全记录，不可篡改（D3.11）
- 变更前 writeAudit（approveAtomGuard 第 10 项）
- 配置中心每次修改 writeAudit（C2）
- PWS 冻结 / 原子正式化 / 合规废弃 / Prompt 修改 = RBAC 红线操作 + 审计

### 2.3 RBAC（D3.11 + A4 + Q 系列）
- 8 角色（展示口径）：普通客户 / 运营 / 产品审核员 / 平台审核员 / 内容审核员 / 系统管理员 / Skill 管理员 / 法审
- 权威口径角色扩展（Q 系列）：BO-07（PWS 冻结）、字典管理员（Q13）、平台级管理员（Q46/Q64）、internal_compliance（Q49）、internal_finance（Q66）
- "业务方"是产品记录里的字段值，不是登录角色；运营人员/客户成功/业务员都属"运营人员"角色（D8）
- 只读角色看不到写按钮（A4）
- 权限矩阵全文见 09 文档 §8

### 2.4 配置中心（C2 → 落地）
- 40+ 配置项（全文见 02 §C2）：阈值/权重/时限/字典/库容全部后台可配，**禁止硬编码**（Q9）
- 统一放"系统配置中心"，每次修改 writeAudit（C2 尾注）
- 已要求"配置功能页面"的项：重生成上限（Q56）、爆款参数（Q61）、KUP 证据三关（Q63）

### 2.5 通用待办 SLA 引擎（Q49/Q70）
- 所有待办类型共用一套时限+升级动作代码，时限各自配置
- 例：类目确认 72h（Q4）、法审 48h（Q49）、原子证据 7 天（Q18）、就绪未冻结 7 天（Q28）
- 24h 未处理变黄置顶，48h 通知上级 + 看板红色角标（Q49）
- 审核台（Q70）：统一列表，按风险（敏感行业/critical）+ 创建时间排序；置信 >0.85 批量通过，低于线逐条审

### 2.6 多租户隔离（SaaS 基础设施）
- 跨客户不查重、永不驳回、互不感知（Q33）
- 租户隔离下客户看不见彼此（Q33）
- 数据隔离 / 套餐 / 试用 / 续费 / 暂停（D3.11 租户管理）
- Guard 校验 tenant_id 一致（PT-FCW-ASM）
- 知识层共享（类目树/模板/通用表达）与产品私域（字段池/原子/PWC/PWS）严格区分（Q24）

### 2.7 模型与成本治理
- 统一模型注册表（per-1M，字段：模型/供应商/输入价/输出价/日预算/状态/fallback）+ 场景路由（Q67）
- 模型日预算：Opus 50 / Sonnet 30 / Haiku 10 美元（line 2103，C2）
- 套餐 token 月上限：trial 50 万等 5 档（line 1466，C2）

## 3. 反跑偏 8 道闸门（D7.1，展示口径）

| # | 闸门 | 规则 |
|---|---|---|
| 1 | 输入 Schema 校验 | 没有产品名、目标语言、内容用途，不允许继续 |
| 2 | 知识边界校验 | 产品层不能调用平台规则改产品原子；平台层不能修改产品白名单 |
| 3 | 输出 Schema 校验 | Skill 必须输出固定 JSON，不允许自由散文 |
| 4 | 术语校验 | 禁止"语义相撞""固定五维""说明书拆解" |
| 5 | 规则前置校验 | 不兼容/不合理/禁用表达，直接阻断 |
| 6 | 置信度阈值 | 低于阈值进入人工确认 |
| 7 | 人工确认闸门 | 高风险类目/原子/规则/最终白名单必须人工确认 |
| 8 | 回放与对比 | 模型输出和人工修改都记录 |

## 7. 【工程建议】技术选型与工程落地方向（新增，非原文，待决策）

> 以下为基于原文事实的工程化建议方向，**不是原文内容**。每项标注推理依据与待决策点；未决策前不得作为实现依据。

### 7.1 应用形态
- **建议**：单体优先（模块化单体，13 模块 → 同仓 package/模块），理由：13 段链是强顺序流水线、共享 PWS/FCW 状态、跨模块事务多；微服务拆分收益低、成本高。待决策：是否预留 service 边界（whitelist-center / compliance-center / feedback-loop 为未来独立化候选）。

### 7.2 数据层
- 关系库（主数据：13 段链实体、状态机、审计）+ 向量库（M2-M4 知识检索）+ 对象存储（素材/成品）+ 缓存（C7 Layer1 模板缓存、结果缓存）。
- **C7 四层兜底的 Layer1 缓存命中（0 token）** 与 **PWC/FCW 复用缓存**是降本关键路径（D7.2 策略 7）。
- 待决策：向量库选型；事务边界（PWS 冻结、FCW 组装须强一致）。

### 7.3 AI 编排运行时
- Skill 注册表（11 字段）+ Orchestrator（触发/串并行/人工闸门/失败/成本/路由）为权威口径已定结构（06 §4）。
- **人工 Gate 实现**：统一审核台（Q70）+ SLA 引擎（Q49）作为全链 Gate 的后端支撑，避免每段各写一套。
- **Prompt 治理**：ChangeProposal + 版本 +0.1 + 只读红线（A4）→ 建议 Prompt 模板存库版本化，不进代码库。
- 待决策：编排器用现成框架（如 LangGraph/Temporal）还是自研（Skill 注册表驱动）。

### 7.4 配置中心实现
- C2 的 40+ 项 → 统一配置表（key/value/类型/校验/出处 Q 编号/审计）；**权重和=1（Q2）与 Σ≤1.0（Q40）做成通用校验器**被多处复用。
- 待决策：配置变更的发布机制（热更新 vs 重启）。

### 7.5 任务队列与异步
- 相撞组合生成（6 池 × 20 条 ≈ 6400 万理论组合）、内容生成、批量审核 → 建议异步任务 + 批处理（D7.2 策略 8）。
- 待决策：队列选型。
- **Q87 实现补登（2026-09-15，02 C1.31 负责人拍板）**：V1 队列选型裁决为**进程内 asyncio 轮询循环**——M8 restock_auto worker（`app/core/restock/`，同构 §7 既有 SLA SweepScheduler，V1 单进程，`LOOM_RESTOCK_WORKER_ENABLED` 默认 false 部署 opt-in + platform_admin 手工触发端点），不引入 Redis Streams/外部队列；多副本广播/单实例调度+补货锁、瞬态失败重试退避后置 V2。原"待决策：队列选型"为设计时点原文，保留不改。

### 7.6 合规与安全
- 合规词库（Q48）三关卡同源 → 建议做成独立规则引擎服务/库，段4/5/10 共用。
- API Key 唯一入口 + 可吊销（Q67/Q60b）；审计不可篡改（append-only）。
- 8 道闸门（D7.1）建议实现为编排层的横切校验插件。

### 7.7 测试与质量
- 10 个辅助系统（D3.12）中，Evaluation Dataset（每 Skill 测试集/回归）、Golden Cases、Simulation Sandbox 直接服务 AI 质量，建议在 MVP 阶段就轻量建立（不等到 V3）。
- 待决策：MVP 是否引入 Simulation Sandbox（可简化）。
