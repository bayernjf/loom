## 2. 逐项决策记录（✅ 2026-09-13 全部采纳建议方案定稿）

### 2.1 应用形态：单体 vs 模块化拆分
- **候选**：A. 微服务拆分 B. 模块化单体 C. 纯单体
- **建议：B（模块化单体，13 模块同仓 package）**
- **理由**：①13 段链是强顺序流水线，PWS/FCW 共享状态、跨模块事务多（段5→6→11 依赖同一批已批准资产）；②微服务拆分收益低、成本高（07 §7.1）；③V1 目标 5-10 客户，单实例可承载（08 D9 V1）。
- **风险**：模块边界腐化（段 8 无独立 WF、段 13 双 WF 的接缝，B16/Q72）——靠契约层文档（04-06）与目录规范（15）约束。
- **预留**：whitelist-center / compliance-center / feedback-loop 为未来独立化候选，模块接口按服务边界设计（07 §7.1）。

### 2.2 编排器：自研 vs LangGraph / Temporal
- **候选**：A. 现成框架（LangGraph/Temporal）B. 自研 Skill 注册表驱动 C. 混合
- **建议：B（一期自研）+ 编排协议与框架解耦**
- **理由**：①Skill 注册表 11 字段 + Orchestrator（触发/串并行/人工闸门/失败/成本/路由）为权威口径**已定结构**（06 §4.2/D3.10），自研是"按规格实现"而非造轮子；②人工 Gate（Q70 统一审核台）+ SLA 引擎（Q49）是 Loom 特色，框架难直接覆盖；③40 个 PT 协议补齐前，框架绑定反而增加学习成本。
- **风险**：编排器自研工作量大——建议编排核心只做"注册表驱动 + 顺序/并行 + 人工闸门插槽"最小集，复杂 DAG 能力二期评估。
- **回滚/切换**：编排协议层抽象（WF/Skill/PT 均为数据驱动），若二期复杂度失控可迁 LangGraph。

### 2.3 数据层：向量库 / 队列 / 缓存
- **候选**：向量库（pgvector / Milvus / Qdrant）；队列（Redis Streams / RabbitMQ / Kafka）；缓存（Redis）
- **建议**：关系库 = PostgreSQL；向量 = **pgvector 起步**（M2-M4 知识检索，09 D3.13）；队列 = **Redis Streams**（相撞/生成/批量审核异步，07 §7.5）；缓存 = Redis（C7 Layer1 模板缓存 0 token、结果缓存，D7.2 策略 7）。
- **理由**：①V1 数据量（5-10 客户）单库可承载；②pgvector/Redis 减少中间件数量，运维成本低；③C7 缓存命中与 PWC/FCW 复用缓存是降本关键路径（07 §7.2）。
- **风险**：6400 万理论组合（Q15 连带）若真量产生成，Redis Streams 吞吐受限——预筛漏斗（Q21）砍 95% 后实际量级可控。
- **切换条件**：向量检索规模 > 千万级或需要混合检索高级特性时迁独立向量库。

### 2.4 配置热更新机制
- **候选**：A. 重启生效 B. 数据库配置 + 变更广播（热更新）
- **建议：B（配置中心落库 + 变更广播）**
- **理由**：①C2 明确"统一放系统配置中心，每次修改 writeAudit"（C2 尾注）；②Q41 每周重算、Q42 单项 ±0.05 等要求运营频繁调整；③40+ 配置项全部后台可配（Q9）。
- **风险**：热更新一致性——建议配置变更走"发布=新版本 + 原子切换 + 审计"，滚动生效。
- **回滚**：配置中心自带版本回滚（每次修改留历史）。

### 2.5 合规规则引擎独立度
- **候选**：A. 独立微服务 B. 独立模块/库 C. 内嵌各段
- **建议：B（独立模块，进程内库）**
- **理由**：①合规词库三关卡同源（段4 定原子/段5 相撞/段10 清洗，Q48）——必须共用一份实现；②但 V1 单实例下独立服务徒增运维（08 V1 目标）；③block_required 一票否决 + 词表生效即扫描（Q51）是强一致需求，进程内调用更可靠。
- **风险**：未来多实例部署时需抽服务——接口层（scan(text, market, industry) → 处置结果）按独立模块设计即可平滑迁移。

### 2.6 辅助系统在 MVP 的取舍（10 辅助系统，D3.12）
- **候选**：全建 / 只建质量三件套 / 都不建
- **建议：只建 Evaluation Dataset + Golden Cases（轻量版），Simulation Sandbox 后置**
- **理由**：①07 §7.7：Evaluation Dataset（每 Skill 测试集/回归）与 Golden Cases 直接服务 AI 质量，MVP 就该有（防红旗 S2 类"Skill 从未运行"重演）；②Simulation Sandbox（上线前模拟）可简化或后置；③其余 7 个（Knowledge Graph/Drift 等）随 V2-V3。
- **风险**：质量基建不足 → 40 个 PT 协议补齐后无回归手段——建议 Evaluation Dataset 与 16 测试策略联动建。
