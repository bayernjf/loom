## 1. 环境与发布

| 环境 | 用途 | 数据 | 说明（建议） |
|---|---|---|---|
| dev | 开发联调 | 样例数据（16 测试数据） | 本地/单实例 |
| staging | 验收 + Evaluation Dataset 回归 | 脱敏数据 | 发布前闸门 |
| prod | 正式（SaaS 多租户） | 生产数据 | 隔离实例或强隔离 |

- **技术栈与中间件（14 定稿 + 15 技术栈）**：应用 Python 3.12 + FastAPI 单进程模块化单体；数据 PostgreSQL 16（+pgvector）/ Redis 7（缓存；多副本 leader 锁：`LOOM_DISTRIBUTED_LOCK_ENABLED=true` 开启，Q89，默认关；restock 瞬态退避 `LOOM_RESTOCK_BACKOFF_BASE_SECONDS=60`/`LOOM_RESTOCK_BACKOFF_MAX_SECONDS=1800`/`LOOM_RESTOCK_BACKOFF_MAX_ATTEMPTS=10`，Q90；DAG 编排同层并发上限 `LOOM_ORCH_MAX_CONCURRENCY=4`，Q91；Streams 异步队列后置 V2）/ S3 兼容对象存储；前端 React + Next.js（Node 运行时仅构建/SSR）；编排定义为 YAML（无独立编排服务）。V1 用 docker-compose 单机即可承载 5-10 客户，K8s/多实例随 V2 客户量评估。M12 驾驶舱只读端点（Q92，`/api/admin/dashboards/token-cost|review-workload`，platform_admin）为 skill_runs/skill_candidates/ops_todos 三表实时 SELECT 聚合，不引入环境变量、后台调度任务或物化表。M12 统一审核工作台（Q93，`/api/review-workbench/candidates|batch-approve`）为 skill_candidates/skill_runs/c1_industry_thresholds 实时 SELECT+内存风险归一并发，新增配置键 `review.batch_pass_confidence`（0.85，迁移 0021 纯配置种子幂等，无业务表 schema 变更），同样不引入环境变量、后台调度任务或物化表。
- **CI/CD 流程**：提交 → 单元/契约测试（16）→ 构建 → staging 部署 → Evaluation Dataset 回归（防红旗 S2"Skill 从未运行"）→ 人工 Gate → prod
  - **Evaluation 回归命令（M10-Q 实现补登，Q77）**：staging 闸门执行 `backend/.venv/bin/python eval/runner.py`（仓库根目录），扫描 `eval/datasets/skills/` 与 `eval/golden_cases/skills/` 全部 YAML 案例，任一失败/错误退出码非零即阻断发布；案例集与 target 契约见 `eval/README.md`。CI workflow 本体随 M12/部署落地（仓库托管平台确认后）。
- **版本与回滚**：应用版本 + PWS/FCW 快照版本分离；回滚中心（09 D3.12 Rollback Center）覆盖模板/原子/规则/Skill/Prompt
- **发布纪律**：AI 相关变更（Skill/Prompt/权重）必须可回滚、可审计（A4 Prompt 治理 + Q63 KUP 回滚）

## 3. 密钥与安全

- 密钥管理：API Key 一 Agent 一 Key 可吊销（Q60b/Q67）；**密钥不入库、不进文档**（本项目 AGENTS.md 红线）
- 访问控制：RBAC 8 角色 + 权威扩展（07 §2.3）；红线操作（PWS 冻结/原子正式化/合规废弃/Prompt 修改）= 角色 + 人工 Gate（line 7674）
- 审计：writeAudit append-only（所有人工操作 + AI 调用）
- 外部回调安全：effect-callback 鉴权 + 限流 + 幂等（11 §2.1/§3）
- 脱敏：AG-SUPPORT 上线前脱敏审核（Q66）；staging 数据脱敏

## 5. 备份与恢复（建议）

- 数据备份：关系库每日全量 + WAL 增量；对象存储（素材/成品）跨区冗余
