# 主数据回填 · 业务方操作指引（纯指引，无技术细节）

> **用途**：private beta 验收前，由业务 / 运营在**真实部署库**里把"够发证的四样"填齐，使平台能产出第一张真实的 `final_id`。
> **本件定位**：它是 `docs/19_private_beta主数据录入模板.md` 的**业务方精简版**——去掉了接口 / JSON / 字段技术细节，只保留「您要做什么、按什么顺序、填哪些字段」。
> **技术人员看完整版**：字段含义、端点、payload 校验见 docs/19 正文（§1–§5）。本件不要求您懂接口或代码。
> **红线**：所有 `【业务方填】` 必须由业务方给真实数，工程侧不代填；空着比乱填好，自检脚本会告诉您缺什么。

---

## 一、先记住：需要两个人

- **录入人（您）**：提供并写入"四样"数据。
- **跑链裁决人**（技术 / 运营）：把内容生产链跑一遍并在审核环节裁决，产出冻结与合规报告。
- 没人跑链，第一张 `final_id` 出不来；且工程替您造的数据**不作数**（违反禁臆造红线）。
- 您做完"填数据＋自检"后，把产品信息交给跑链人即可。

---

## 二、开始前准备

1. 一个正在运行的系统环境（staging / 真部署），连着**真实的数据库**。
2. 数据库连接信息（技术人员提供）：`LOOM_DATABASE_DSN`。
3. 一枚 `operations` 权限的访问令牌——**只有最后发证那一步才需要**（由跑链人准备）。
4. 您自己定一个**平台代码**（英文大写短码，如 `EXAMPLE`），全系统一致使用。原来的平台目录已丢失，类型名由您定。

---

## 三、操作步骤

### 第 0 步 · 定平台码 + 选首个产品
- 定一个平台码（如 `EXAMPLE`），后面所有"平台"字段都用它。
- 选一个**真实产品**作为第一张 `final_id` 的载体。

### 第 1 步 · 建产品空间
- 按运营 SOP（docs/21 段1）录入该产品，得到一个**产品空间编号**。后面所有材料都挂在它下面。

### 第 2 步 · 用模板一次性填"四样"
- 技术人员给您 `seed_master_data_template.py` 这个填数脚本。它本身带占位符，您把每个占位符换成真实业务值（字段见第四节）：
  - **发布位**：至少填 平台 / 编码 / 名称 / 类型；分数、风险、来源链接等**可不填**。
  - **PCP 平台配置**：填 平台 + 模板码（四选一），权重留空用默认。
  - **三包（策略 / 结构 / 表达）**：各填一条。
- 填之前先跑"预览"看会写入什么、**不真正入库**；确认无误后再正式写入。
- ⚠️ 占位符没填完，脚本会**拒绝执行**，防止把"待填"写进库。

### 第 3 步 · 自检"够不够发证"
- 填完后跑 `check_master_data.py` 这个自检脚本：
  - 显示 **齐备** = 四样数据都到位，可以进入跑链。
  - 显示**还差哪类**（如"缺 PCP""三包不齐"）= 补上对应数据再跑。
  - 脚本会**单独提示**"敏感领域字典"是否为空——首批产品请**有意避开**打算作为敏感类目管理的行业，否则会卡在等法务审核（见第五节 ⚠️）。

### 第 4 步 · 交给跑链裁决人（关键，别跳过）
- 把 **产品空间编号 / 平台 / 发布位编码 / 目标** 交给跑链人，由其跑完内容生产链并在审核环节裁决。

### 第 5 步 · 发证（跑链人操作）
- 跑链人用令牌调用发证接口，成功即产出 `final_id`。若被拒，系统会告诉缺哪一路材料，补上重跑即可（不会静默失败）。

---

## 四、您需要填写的字段表

> 以下字段的具体值由您按真实业务判断填写（脚本与完整模板里有逐键说明）。**不要编造**——空着比乱填好。

### 表1 · 发布位（至少 4 项必填，其余可空）
| 字段 | 是否必填 | 说明 | 填什么 |
|---|---|---|---|
| 平台 platform | 必填 | 与第 0 步定的平台码一致 | `【业务方填】` |
| 编码 code | 必填 | 全系统唯一 | `【业务方填】` |
| 名称 name | 必填 | 中文名 | `【业务方填】` |
| 类型 slot_type | 必填 | 您定义的类型码 | `【业务方填】` |
| 最大字数 / 最短·最长时长 | 可空 | 不卡发证 | 留空 |
| 四维分（流量 / 安全 / 转化 / 承载） | 可空 | 人工评估分，**不卡发证** | 留空 |
| 风险 risk / 来源链接 source_url / 闸门档 gate | 可空 | 不卡发证 | 留空 |

### 表2 · PCP 平台配置（每条 产品×平台 1 条）
| 字段 | 是否必填 | 说明 | 填什么 |
|---|---|---|---|
| 平台 platform | 必填 | 同第 0 步 | `【业务方填】` |
| 模板码 template_code | 必填 | 四选一：短视频型 / 社区讨论型 / 图文种草型 / 电商型 | `【业务方填】` |
| 权重 weights | 留空 | 用模板默认 | 不填 |

### 表3 · 三包（各 1 条 active）
| 包类型 | 必填字段（键名） |
|---|---|
| 策略包 CSP | 目的 goal / 阶段 stage / 角度 angle / 强度 intensity / 行动号召 cta / 情绪 emotion |
| 结构包 CSTP | 结构 struct |
| 表达包 CEP | 语气 tone / 人称 perspective / 是否显性 explicit / 软化方式 soften |

## 五、⚠️ 两个容易踩的坑

1. **别为这些等工期**：四维分、风险、来源链接、时长类、闸门档、fit 权重矩阵、slot_type_defaults——**全部不卡发证**。首批不必向业务方索取打分；把这些列进首批清单，是最常见的"主数据一直回不来"的**假阻塞**。
2. **避开敏感类目行业**：系统有一张"敏感领域字典"，目前是空的 ⇒ 首批默认放行。但一旦合规团队启用了某个敏感类目，命中产品就会转 48 小时法务审核待办。首批选产品时请**有意避开**打算启用为敏感类目的行业，否则"打通第一张 `final_id`"会挂在等法务上。

---

## 六、完成标准

系统里出现一张 `final_id`，其材料与审计记录指向**真实业务数据**（不是测试、不是工程替造），即首批完成。

---

## 七、审计溯源提醒

所有填写操作请写**真实可辨识的操作人**（如"运营-张三"），不要多人共用一个账号名——后续对账靠它。
