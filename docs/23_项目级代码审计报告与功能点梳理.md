## 4. 安全审计（重点）⚠️

### 4.1 根因：鉴权门控默认关闭 → 信任自报角色（高危，已确认）
- `core/config.py:112`：`staff_auth_enabled: bool = False`。
- `core/rbac/__init__.py:45-60`：门控关闭时退化为 `if not any(role in actor.roles ...)`——**完全信任请求体自报 `roles`**。
- 含义：当 `staff_auth_enabled=False`（当前默认），任何写请求只要 body 里写 `"roles": ["operations"]` 即可通过 `require_any_role` 校验。这是"任何人可伪造运营角色"的系统性风险。
- 缓解现状：仅 `mcp/router.py:39`、`a2a/router.py:74` 走真 Bearer + SHA-256 验签；其余 staff 端点依赖关闭的门控。

### 4.2 五处写口绕过 `require_any_role`，自判角色（高危，已确认）
下列 service 内部自判 `actor.roles` 或 `_require_ops/_require_owner/_require_role` **不触达** `require_any_role`，故永不校验 staff PAT：

| 模块 | 证据 | 涉及的写端点（router） |
|---|---|---|
| atom Gate | `product/atom/service.py:335,415,437,582,623,680-682,749` | `router.py:208` approve / `:227` batch-approve / `:246` reject / `:304` cluster-resolve / `:325` risk-override / `:348-462` freeze/unfreeze/suspend/resume/deprecate/archive/reject |
| 段9/10 策略包 | `decision/layer_strategy/service.py:49-51` | `router.py:49,71,87` create/update/archive |
| ~~段11 终稿白名单~~ | ~~`final/final_whitelist/service.py:102-104`~~ | ~~该模块全部写口~~ **〔订正 2026-10-01：此条不成立，见 §4.2 订正〕** |
| 段7/8 平台适配 | `platform/platform_adaptation/service.py:75-77` | 该模块全部写口（9 个写端点，`router.py:97,109,125,161,190,210,254,290,310`） |
| PWS 冻结/吊销 | `product/whitelist_center/service.py:68-70` | `router.py:78,109` |

- 判定：**高**（**4 处**，原报告称 5 处）。这些写口即便 `staff_auth_enabled=True` 也不校验 staff PAT（只信任 body 自报角色）。Q106/Q107 客户身份口径（roles=[]）与运营写口的守卫混用，缺乏统一防线。

**§4.2 订正（2026-10-01，Q241 复核）**：原表第 3 行「段11 终稿白名单 — 该模块全部写口」**不成立**。回代码实测：`final/final_whitelist/router.py` 只有 **2 个**写端点，且**两个都**带 Q203 的 `require_internal_actor(OPERATIONS)`（`router.py:60` 的 `POST /api/fcw/assemble` 与 `router.py:102` 的 `POST /api/fcw/assembly-tasks`，依赖在 `:64` / `:106`）——即**已在路由层校验 staff PAT**，service 内的 `_require_ops` 只是 worker 内部兜底。其余四条经逐条复核**成立**（复核命令与结果见 §10）。

### 4.3 租户隔离：tenant 与身份未绑定（高危，已确认）
- `core/tenants/service.py:5` 自述"Actor 无租户归属，本切片不做成员绑定"；
- `product/atom/service.py:332`、`fieldpool/modeling/condition/decision` 等普遍 `session.get(Model, id)` **不校验归属**；
- 正面样本：`content/service.py:133-147` 按 id 单查后 `tenant_id` 反查、`150-158` 列表过滤；`core/exports/service.py:258-263` 强制 `tenant_id` 必填。
- 遗留易复发点：`core/exports/service.py:458-459` `get_job(session, job_id)` 无租户过滤（当前路由未用）。
- 判定：**高**，与 4.1/4.2 同源——缺少"身份↔租户"统一绑定层，跨租户访问无系统性防线。
