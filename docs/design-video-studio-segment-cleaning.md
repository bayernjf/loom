## 2. 数据契约缺口（为什么不能直接写代码）

1. **视频 body 只是 `video_ref` 引用字符串**（Q323）：不存在分段脚本实体、不存在视频文本产物、不存在视频清洗数据源。
2. **分段脚本 / 对象存储 / 段12 视频业务链路**：Q252（docs/05 L371、docs/02 C1.196）登记为「段12 视频规格原文未给【待补】、**禁代裁/禁臆造**」。
3. **真视频模型未接线**：供应商 agnes-video 的 `mode` 合法取值原文未给（Q254 实测五种取值均 400）。
4. **CCR 输入是文本 `text_blob`**：成片视频没有可喂给 CCR 的文本；要对视频做内容清洗，须先有语音转写/字幕/脚本等文本化产物，而转写能力同属段12【待补】。
5. **原始需求只有一句话**：docs/01 L140「video-studio 四模块：白名单信息区/分段编辑器/内容清洗区/生成结果区，AI 质量评分阈值 0.85 上线（line 5196）」；基准 HTML 已永久丢失（Q115），四模块详细交互、字段、状态机无原文。
6. **WF-07 操作面无形态规格**：docs/12 §3.2 只定四 Skill 的输入/输出契约，未定"在哪个页面触发、候选是否持久化、人工采用后写回哪张表/由谁裁决"。

> 铁律约束（全部候选都遵守）：AI 只产候选、人工 Gate 裁决；`final_id` 是唯一成品出口；只读消费 frozen/FCW 原料，不在 video-studio 内新生成 final_id、不绕过既有 Gate。

## 3. 分段编辑器候选

| 方案 | 内容 | 评价 |
|---|---|---|
| **甲（推荐）** | **只读分段视图**：按 FCW 既有 structure/expression 层的结构化文本，切分为只读分段（段落/分镜占位）时间轴，每段标注来源层与文本，不新建分段实体、不臆造时长/镜头/转场字段；页面显式标注"可编辑能力（拖拽/改词/时间码/重排）随段12 视频规格到位后开放"。 | 纯只读消费既有 FCW，与已落两屏同口径，**零臆造、可立即落**；代价是 V1 不是"可编辑器"。 |
| 乙 | 建最小分段实体（segment：seq/text/start/end 子表），支持人工编辑文本与时间码。 | 时间码、分段粒度、与 video_ref 的关系均无原文，等于自创段12 数据模型，**违反 Q252 禁臆造**；且真视频未接线无法验证。**不建议。** |
| 丙 | 分段编辑器整体后置到真视频模型接线（mode 解锁）后随 video-studio 独立点工；V1 仅灰置占位"随视频生产能力开通"。 | 零臆造、零半成品；代价是四模块长期只有两屏。 |

**推荐甲**；若评估认为只读视图对运营无实际价值，可取丙灰置。乙案禁止。

## 5. WF-07 操作面候选

四 Skill 已可经模型网关 `invoke` 返回确定性字典值候选（Q326），缺运营触发与裁决面。

- **触发**：在段9 三包/组装相关管理页新增"AI 选包建议"入口，按当前 PS×platform×slot 组装有界变量后调用对应场景；前置闸（PS 存在、goal 必填、池字典非空）在端点层校验，缺 goal/body 返回 422（与 §3.2 强校验一致）。
- **候选持久化**：
  - **甲（推荐）**：候选落既有 `skill_candidates`（state=pending_review），复用 Q93 统一审核工作台与 skill7 decide 流程，人工 decision 后才生效——与 Q85 字段池方案、Q93 审核台完全同构，**不新建表、留痕、AI 不自动生效**。
  - 乙：候选仅在会话/前端展示不落库，运营手工抄录。无留痕、无 Gate，**违反候选必经人工裁决的惯例，不建议**。
- **采用写回**：goal/struct/tone/style 被采用后，**预填到三包/包配置的草稿**，再走既有包 create/update 审批（`layer_strategy`），不直接改 active 包、不绕过包 Gate。
  - **接缝（已裁决 Q328）**：写回的确切目标＝**包配置草稿（预填）走既有包 create/update 审批**、裁决角色＝**operations**（原列为审核表 D5，2026-10-10 负责人批「按推荐甲」闭合）。
- **丙**：操作面整体 V2，V1 维持现状（仅场景注册，无 UI）。

**推荐甲（含 D5 先定写回目标与角色）**；若暂不具备接线条件，可取丙维持现状。
