## 0. 仓库定位与规模概览

Loom＝AI 驱动的 13 段链私域内容生产白名单 SaaS 后台（产品录入 → … → `final_id` 组装 → 内容生成 → 反馈回流）。

| 组件 | 技术栈 | 规模（实测） | 角色 |
|---|---|---|---|
| `backend/` | FastAPI + SQLAlchemy 2 async + Alembic，Python 3.12 | app **39,569 LOC**／tests **41,698 LOC**（505 py 含测试）；**66 迁移**、真 PG16 实测 **77 表 / 845 列**、openapi **227 paths** | 唯一业务后端 |
| `frontend/` | Next.js 15.5.25（standalone）+ React 19 + next-intl，TS 5.7 | **122** ts/tsx；20 管理屏＋客户页 | 管理台＋客户台（RSC/Server Action 服务端取数） |
| `middleplatform/` | — | **0 个代码文件**（webhook/sdk/export 三个空目录） | V3 预留空壳（README 描述与实况不符，见 P3-1） |
| `runtime/` | YAML | 19 个 skill.yaml＋5 个 WF-*.yaml | 编排声明，由 backend `skill7/registry.py` 经文件系统相对路径加载 |
| `eval/` | Python runner + YAML 用例 | runner.py＋targets.py，**101 个评测用例** | CI 回归门（实测 101/101 通过） |
| `infra/` | docker-compose×6 overlay + Caddy + Prometheus/Grafana + WAL/备份/演练脚本 | 21 文件 | 私有 beta 单宿主部署与演练 |

组件边界总体清晰：frontend 只经 server-only `lib/api.ts` 访问 backend（密钥不进浏览器包）；backend 是唯一写库方；runtime/eval 是纯声明/数据；middleplatform 为空。**跨组件耦合点两处**：① backend 经 `Path(__file__).parents[4]/runtime` 文件系统相对路径读 runtime/（`backend/app/core/skill7/registry.py:14-16`，Dockerfile 显式 `COPY runtime/ /runtime/` 兜底，镜像内成立）；② `pyproject.toml` 的 `model-hub-client` 依赖指向**仓库外**兄弟目录 `../../model-hub/clients/python`（见 P2-2）。

## 2. 逐条发现

### P0（可利用的安全/资损面）

#### P0-1 内容底座 `/api/v1/content/*` 无鉴权写口，hub 配置下直接花真 LLM token

- **位置**：`backend/app/core/content_base/router.py:69-118`（`POST /requests`、`POST /{candidate_id}/review`、两个 GET）；`service.py:46-54`（`_default_producer`：hub 已配置→`LLMContentProducer`）、`service.py:75`（`produce(request)` 真实调用）。
- **证据**：
  - 路由只有 `Depends(get_session)`，无 staff/client/agent 任一凭证依赖；仓内自检工具 `backend/scripts/route_auth_matrix.py` 实测列入 `no-route-level-gate`（132 ops 之一），且 **不在** `tests/integration/test_write_gate_wiring.py` 的 `GATED` 清单、不在 `tests/unit/test_content_route_auth_wiring.py` 的覆盖范围（该文件只覆盖 `app/content` 路由）。
  - 网关把 `/api/*` 整段反代公网（`infra/caddy/Caddyfile` 「3) 机器接入面」`handle /api/* { reverse_proxy backend:8000 }`），无路径级排除。
  - 未配置 hub 时退化 `DeterministicProducer`（不花钱），但仍是无鉴权 DB 写入＋审计行灌水；`review` 口可把他人候选置 confirmed/rejected（`service.py:107` 起）。
- **影响**：公网匿名调用即可提交内容生成请求。hub 已配置（生产形态）时＝**无鉴权花真 token**；未配置时＝候选表/审计表垃圾写入与内容管线状态篡改。
- **修复建议**：给该 router 加 `require_agent_key`（Q88 机器凭证，`/api/v1/content` 本就是系统间消费面）或 `require_internal_actor`；同时在 `test_write_gate_wiring.py`/`route_auth_matrix.py` 的清单里显式登记其闸型，防回归。

### P1（严重）

#### P1-1 客户面 intakes/effects/exports 端点零凭证，跨租户读写只凭可猜测的 tenant_id

- **位置**：
  - `backend/app/product/product_intake/router.py:56-245`（`GET /api/intakes` 列表、`GET /{id}`、`PATCH /{id}/profile`、`POST /{id}/transitions` 等均无凭证依赖；仅 `ops-queue` 有 `require_ops_view` 自报角色闸）；
  - `backend/app/core/effects/router.py:95-197`（`POST /api/effects/backfill`、`/upload`、`/upload-excel` 无凭证）；
  - `backend/app/core/exports/router.py:39-110,147-213`（`GET /api/exports/fcw.csv|json`、`POST /api/exports/jobs`、`GET /jobs/{id}/download` 无凭证，仅按 query `tenant_id` 过滤）。
- **证据**：`route_auth_matrix.py` 实测上述均为 `no-route-level-gate`；全局仅挂 `staff_auth_context`（`backend/app/main.py:178`），其对无令牌请求不拦截（`staff_auth/deps.py:64-69` 直接 return）。README 自述 2026-10-30 起客户令牌只覆盖「内容口（列表/详情/裁决/正文编辑/语言目录）」——intakes/effects/exports 不在其列。租户默认名 `beta-tenant` 明文见 `infra/docker-compose.yml:116`。
- **影响**：能打到后端（公网网关 `/api/*` 即可）的任何人可读取任意租户录入单（产品资料明文）、推动录入单 14 态状态机、回填伪造效果数据、下载任一租户 published 白名单。backfill 写口因有「content_id 必须命中本租户非 discarded 成品」的校验而风险略减（需先知 UUID），intakes 列表与 exports 下载则仅需 tenant_id。
- **修复建议**：按 content 路由同法接 `require_client_actor`（intakes、效果回填）与 Agent Key（exports 中台面）；短期可在网关对 `/api/exports/*`、`/api/effects/*` 加 IP allowlist 或独立路径鉴权兜底。

#### P1-2 staff 身份门控默认关（`staff_auth_enabled=False`），门控关时 154 个写口接受自报角色

- **位置**：`backend/app/core/config.py:118`（默认 False）；`infra/docker-compose.yml:93`（`${LOOM_STAFF_AUTH_ENABLED:-false}`）；`backend/app/core/rbac/__init__.py`（门控关时 `require_any_role` 只校验 body/query 自报 roles）。
- **证据**：`route_auth_matrix.py` 实测 270 操作中 157 写操作，其中 **154 个写口**无路由级凭证依赖（门控关时靠服务层自报角色校验）。本地 `infra/.env` 已显式 `LOOM_STAFF_AUTH_ENABLED=true`（gitignored），但任何按 compose 默认值起栈的部署形态门控都是关的。
- **影响**：这是 docs/23（2026-09-30 审计）已点名的高危项的**残余形态**——Q178/Q203/Q242 把硬闸备好、E1.1 发证等 34 个写口已升级为「不看门控也要真令牌」，但剩余写口在门控关时仍可凭 `roles:["platform_admin"]` 自报通过。任何绕过网关直连 backend 的路径（网关误配、同网段、SSRF 跳板）即全盘失守。
- **修复建议**：把默认翻转为 true（或至少在 gateway overlay 的 compose 里显式置 true 而非继承 false 默认），把「门控关＝可自报」的兼容期收口到仅本地 dev；V2 会话派生身份落地前这是最高杠杆的单点动作。

#### P1-3 Next.js 15.5.25 命中 4 条生产依赖安全公告（1 critical + 3 high），修复版已出

- **位置**：`frontend/package.json`（`next: ^15.1.0`）；实测安装 15.5.25。
- **证据**（2026-11-02 本机 `npm audit --omit=dev` 实测）：
  - `next` critical：**GHSA-2464-fhr4-w9xw**（Image Optimization API 未鉴权 RCE，`<=15.5.27`）；high：GHSA-p3m5-59mp-jv5r（App Router Server Actions DoS，`<=15.5.27`——本前端大量使用 Server Actions）；另两条 moderate 缓存投毒（`>=15.0.0 <15.5.27`，self-hosted 形态正中）。
  - `postcss` high（GHSA-6g55-p6wh-862q 等 3 条）、`sharp` high（CVE-2026-96889）、`source-map-js` high（GHSA-68fv-2mgg-jv7q）。全部 `fix available`。
- **影响**：自托管 standalone 部署直接暴露 `/_next/image` 与 Server Actions 面。图像优化 RCE 的可利用性以 SVG 配置为条件（本仓未开 `dangerouslyAllowSVG`、未用 `next/image`，缓解但未确认彻底免疫——公告原文范围句在审计输出中被截断，未确认）；Server Actions DoS 无前置条件。
- **修复建议**：`npm update next`（≥15.5.28 或公告修复版）并重跑 typecheck＋8 checker＋next build；把 `npm audit --omit=dev` 挂成 CI 信息门。

### P2（质量/性能/构建）

#### P2-1 mypy 存量基线 117 错/38 文件，且不是 CI 门

- **证据**：`cd backend && .venv/bin/python -m mypy app` 实测 `Found 117 errors in 38 files (checked 255 source files)`；错误类型分布 arg-type 27／union-attr 26／assignment 18 为主，含 `app/main.py:123,134,160,163` 的 worker 列表类型混赋。CI 只跑 ruff（`.github/workflows/ci.yml` backend job），mypy 不进任何门；handoff（2026-10-30 批）自述「router/main 余 8 个为基线错误」——**实测基线已涨到 117**，账面严重滞后。
- **影响**：类型门形同虚设，新增错误的「新增 vs 存量」分界只能靠人肉 stash 对照（handoff 里正是这么做的）。
- **修复建议**：要么按模块分批清零后挂 CI，要么给 mypy 配 per-module ignore 让「新模块 0 错误」可机械执行。

#### P2-2 生产镜像缺 `model-hub-client`，hub 投影在容器内静默降级

- **位置**：`backend/pyproject.toml`（`model-hub-client` 依赖，source＝仓库外 editable 路径 `../../model-hub/clients/python`）；`backend/requirements.lock`/`requirements-dev.lock` **均不含**该包（grep 实测零命中，仅 `uv.lock:790` 有 editable 记录）；`backend/Dockerfile` 只 `pip install -r requirements.lock`。
- **证据**：`app/core/model_registry/hub.py:115` 函数内 `from model_hub_client import ModelHubClient`；lifespan 引导与 5min 刷新线程均为宽泛 `except Exception` 只记 warning（`main.py:88-103`、`hub.py:162,418`）。
- **影响**：镜像内即使配置了 hub env，投影同步永远 ImportError→warning→回退 0600 缓存（新镜像无缓存）＝hub 相关路由退化。生产是否启用 hub **未确认**；若启用即功能静默失效。
- **修复建议**：CI 已 clone 兄弟仓（`ci.yml` backend job），Dockerfile 同法 `COPY` 兄弟 client 或改发私有 index 的正式包；至少加一条镜像内 `python -c "import model_hub_client"` 的构建断言。

#### P2-3 有界 N+1：字段池/建模持久化循环内逐条查询

- **位置**：`backend/app/product/fieldpool/service.py:181-200`（`_persist` 逐 item `select(G2FieldCandidate)`）、`app/product/modeling/service.py:526-540`（Layer4 逐 proposal 查同名候选）。
- **影响**：循环基数＝字段维度/提案条数（个位数到几十），V1 规模无感；属结构性 N+1 模式，量产后字段池重提是热点路径。
- **修复建议**：改为一次 `WHERE field_name IN (...)` 取出后内存匹配。优先级低，登记即可。

#### P2-4 导出文件名直接拼接未消毒的 `tenant_id` 进 Content-Disposition

- **位置**：`backend/app/core/exports/router.py:59,93`（`filename = f"fcw-{tenant_id}.csv"` → `_page_headers` `f'attachment; filename="{filename}"'`）。
- **影响**：tenant_id 含 `"` 时响应头畸形（CR/LF 会被 HTTP 层拒，纯引号不会）；攻击者只能破坏自己那份响应，实际危害小，但属输入未消毒进头部的坏模式。
- **修复建议**：文件名白名单化（`[^A-Za-z0-9._-]` 替换为 `_`）。
