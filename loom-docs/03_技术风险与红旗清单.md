## B1. 红旗清单（S/A/B 三级）

> 说明：每条红旗保留原文描述 + 裁决/处置状态。已裁决项在 §C（02 文档）中有关键 Q 编号；未裁决项标【待裁决】。

### S 级（不解决无法开工）

**S1. 主链前半段数据服务未交付**：line 559 自注「外部脚本未随项目交付（frontend/、assets/ 不存在），相关模块显示'未加载'占位」；`productSpaces/fieldPools/atoms/intakes/pws/platformAdaptationCandidates` 初始全为空数组，段 1-6 真实数据层缺失，原型仅少量硬编码 mock。
→ **裁决**：开发前置项，见 01 §7 第 0 步①。

**S2. 关键 Skill 在原型中未启用**：SK-LIB-PLATFORM-ADAPTER（段 7 核心）与 SK-LIB-KUP-PROPOSE（段 13 核心）state=pending_review、runs_7d=0——主链的平台适配与知识进化两个枢纽只有协议、没有运行证据。
→ **裁决**：实现即首次落地，见 01 §7 第 0 步②、02 §C1.6/§C1.13 未做标注。

**S3. 回流数据供给断裂**：catFeedback 需要内容级 avg_ctr/avg_read/avg_conv，但评论/私信/群聊/Reddit/Telegram 等发布位平台不提供内容级 API；私域转化（加 WhatsApp/留邮箱）无法自动归因回单条内容。API-effect-callback 标 P1 且假设客户回传。飞轮画得通、喂不饱。
→ **裁决**：Q60 采纳外部 Agent 推送制 + 指标降级，见 02 §C1.13。

**S4. 评分体系无公式**：平台四维分（traffic/safe/conv/load）无聚合算法，fit_score 实为手填常量（PT-PCP-V1.6 提案自证当前不可算）；C1 五信号权重是样本反推的 mock，图像信号如何提取未定义；PWC「品类乘数」评分仅有名字无公式。
→ **裁决**：Q34（四维聚合）、Q2（信号权重配置化）、Q22（PWC 评分）分别定稿，见 02 §C1.6/§C1.1/§C1.4。

### A 级（设计矛盾，实现前需修正）

**A5. PWS 版本更新 vs 已发布 final_id 一致性未定义**：旧 final_id 指向旧快照，失效/共存/重生无规则；DRIFT-DETECT 只检不修。
→ **裁决**：Q29 重冻三档 + Q30 换版四行处置，见 02 §C1.5。已销账。

**A6. FCW「6 路 product_space_id 一致」对通用包形同虚设**：CSP/CSTP/CEP/CCR 原子来自跨产品共享的 layerSpaces，本无 product_space_id 归属——要么通用包强绑 PS 破坏复用，要么该 Guard 空转。
→ **裁决**：Q52 区分"底座选项"与"配置实例"，Guard 校验实例归属。已销账。

**A7. 冷启动阈值三处不一致**：conf<行业阈值（0.80-0.90）vs hit_rate<0.6 vs <0.4，指标与阈值互相矛盾。
→ **裁决**：Q1 统一 conf 单指标、hit_rate 废弃。已销账。

**A8. platformRules 冲突消解缺失**：同级多规则命中（如两条 platform+slotType 都 match、effect 冲突）无合并语义，仅「优先级最高者胜」一句；<300 条覆盖 10 万格子的稀疏假设在跨层 R-X 规则加入后组合爆炸。
→ **裁决**：Q36 取最严 + 保存时静态查重。已销账。

**A9. KUP 统计上不成立**：以 field_impact.lift 推断单字段边际因果贡献，观测数据混杂严重、样本量小；「爆款」无判定标准（status:'爆款' 为手工标注）。
→ **裁决**：Q63 证据三关（30 条/0.5%/2 期）+ 相关性非因果标注；Q61 爆款中位数倍数法。已销账。

**A10. 权重「Σ≤1.0」多处声明但无强制校验点**；WEIGHT-UPDATE 自动更新未说明如何维持约束。
→ **裁决**：Q40 统一校验器，保存/重算入库前强制。已销账。

**A11. AI 治理自相矛盾**：红线「Agent 不能批正式对象」，但存在 USR-CO-AI-* 内部 AI agent 以 internal_compliance/internal_finance 角色接管 U1+U2、可被授权为 owner（line 1613）。
→ **裁决**：Q66 第一期 AI agent 一律不持 owner/审批角色，内部合规/财务角色只配真人。已销账。

**A12. 「去 AI 痕迹 + AI 质量分 0.85」自指**：用 AI 检测并消除 AI 痕迹不可靠，且该分数与真实平台限流/封号无相关性校准。
→ **裁决**：Q57 质量分降级"辅助参考"、待回流校准。已销账。

**A13. content_goal 配比无消费方**：ratio_max/min 定义后，主链无任何按配比调度内容量的环节。
→ **裁决**：Q44 落地为软提示仪表盘，不做硬闸门。已销账。

**A14. template field_list 存在 `fid:'-'`**（C7 缓存返回项无 fid，line 710）：无法回链 G2 做同义词/usage 统计，字段治理链断裂。
→ **裁决**：Q68 禁止 fid:'-' 落库 + 存量上户口扫描。已销账。

**A15. WF-06 注册数不一致**（官方注 5、实挂 6）；两套模型注册表单价口径不同（per-1K vs per-1M），成本核算会算错。
→ **裁决**：Q67 两表合并 + 统一 per-1M + 场景路由。已销账。

### B 级（缺口，需补规格）

**B16. 段-WF 映射接缝**：段 8 无独立 WF、段 2 并入 WF-01、段 13 由 WF-11+WF-12 共担——主链段与 WF 的映射存在接缝，实现时需明确归属。
→ **裁决**：Q72 以 §A1 CHAIN_13 表为准，不新增 WF。已销账。

**B17. PT 协议占位**：40 个 PT 协议中 34 个是占位（「详情待补充」），仅 6 个旗舰协议有完整 constraints/guards。
→ **裁决**：定优先级——先补第一阶段主链（段 1→6→10→11→12）用到的协议，余随阶段补（02 §C1.16 说明）。
> ⚠ 口径备注：01 文档 §3 中实际列出 7 个带约束的 PT 协议（PT-FP-PLAN-V2.0 / PT-ATOM-EXP-V1.3 / PT-PLATFORM-ADAPTER-V1.0 / PT-PCP-V1.5 / PT-COMPLIANCE-V2.0 / PT-FCW-ASM-V1.0 / PT-ART-GEN-V1.5），与 B17 原文"6 个旗舰"计数不一致——原文如此，此处保留 B17 原表述，不擅自改。

**B18. PWC 相撞的组合生成算法**（如何从原子集生成候选组合、如何控组合爆炸）HTML 未给出，仅有 Skill 名与校验/评分环节。
【业务方参考：D5_原子相撞检测_详细说明书】业务方版给出了完整算法：合理性预筛（100%→~5%，4 规则）→ 6 种相撞检测（合规/语义/场景/偏好/平台/冷启动）→ 权重计算（历史 0.40+语义 0.25+市场 0.20+新颖 0.15）→ 套餐限量 30/80/200。**该算法与 HTML 的 PWC/PWS 体系术语不同（业务方无 PWC/PCP/FCW 概念），若采纳需做映射改造，此处仅作为补规格时的候选参考。**
→ **裁决**：Q21 采纳漏斗骨架（预筛→检测→评分→限量），全环节配置化。已销账。

**B19. 审核运营机制缺规格**：审核（Gate/HumanGate）在 HTML 中只有「审核 Gate + reviewer 角色」概念，无审核任务分配、SLA、批量审核、抽检等运营机制规格。
【业务方参考：F3_审核工作流引擎_详细说明书】业务方版有完整审核引擎规格（6 场景、SLA 24h/4h/1h 三档、分配算法、批量审核阈值 >0.85 一键过、10% 抽检）。若需要审核运营机制可参考，但其任务类型（维度/字段/原子/白名单审核）与 HTML 的 Gate 点位需重新映射。
→ **裁决**：Q70 第一期轻量版（统一审核台 + 通用 SLA 引擎 + >0.85 批量通过）；分配算法/6 场景细分/抽检列第二期。已销账。

**B20. 白名单消费侧契约缺规格**：只有页面清单（白名单查询 API/使用记录上报/效果回流 API），无接口契约与消费规则（按什么排序取、取后状态如何流转——HTML 条件包状态含「待用/已用/爆款/冷却」但流转触发条件未定义）。
【业务方参考：E1_白名单组装_详细说明书】业务方版定义了消费接口 `/api/whitelist/consume`（按权重取 + 自动 usage_record + 同平台同账号同发布位不可重复）与 5 池保底补给机制（保底 50/上限 200/冷却 5min）。同样需术语映射后方可采纳。
→ **裁决**：Q71 按评分从高到低取 + Q24 去重 + 池健康度三档（target 100/min 70/critical 50）保底补给。已销账。
